weld, the linker

weld links relocatable objects into an executable, in place of ld, lld or mold. Dynamic executables on x86_64 Linux work through the gcc driver today. Static glibc does not, and dynamic linking on the other architectures does not.

Install

The crate is lamina-weld; the binary it installs is weld. cargo install lamina places weld beside the compiler, so a Lamina install needs nothing further; cargo install lamina-weld gets the newest release{{#if weld_version}}, {{weld_version}}{{/if}}, which is the source this page describes, when you want a weld of your own. lamina looks for weld beside itself before PATH and refuses one older than the version it was built against; set LAMINA_WELD to a path to override. It needs Rust 1.88 (its manifest sets rust-version = "1.88"). From a checkout, run cargo install --path weld. There are no feature flags.

With the Lamina driver

$ lamina app.lamina -c weld
$ lamina app.lamina --assembler ras -c weld

In place of ld

Use a prefix directory holding an ld symlink and point the compiler at it with -B. Unlike ras, weld does not look at argv[0]; the symlink is only there so the driver finds it. The argv[0] claim was not tested.

$ mkdir -p toolchain
$ ln -sf "$(command -v weld)" toolchain/ld
$ ln -sf "$(command -v ras)" toolchain/as
$ gcc -B"$PWD/toolchain/" hello.c -O2 -o hello

That builds a position-independent executable through both of our tools, with gcc supplying the CRT objects and the interpreter path as it does for any linker.

-fuse-ld=weld does not work. gcc only accepts the linker names it was built to know, and clang rejects it the same way. -B is the way in.

Everything gcc's collect2 passes on a normal Linux link is accepted, which is why the -B route works at all.

Formats and architectures

Mach-Ox86_64 arm64Mach-O executables are written and checked with file. The testcase suite passes on macos-latest (arm64) in CI. Ad-hoc codesigning was not checked.
PE32+x86_64COFF input must be AMD64. Any COFF input produces a PE32+ executable, whatever the output name.

ELF input is ELF64 little-endian only, so -m elf_i386 and 32-bit objects are refused.

Where it is not a drop-in

Static glibc failsgcc -static stops at static GNU IFUNC is not supported: __new_memcpy; resolver calls require IRELATIVE relocations and startup relocation tables. glibc selects its string and block-copy routines through IFUNC resolvers, and nothing emits IRELATIVE yet. -static is for freestanding objects and plain archives.

Thread-local storage works.tdata and .tbss are laid out under PT_TLS, local-exec and initial-exec relocations are applied against the thread pointer, and a global-dynamic sequence relaxes to local-exec. Local-dynamic TLS, and a thread-local symbol imported from a shared library, are errors. On PE, weld synthesizes _tls_index and builds the PE TLS directory. On Mach-O, AArch64 thread-local access goes through TLV descriptors in __DATA,__thread_vars and the __tlv_bootstrap thunk. An earlier version of this page and of weld's own README said TLS inputs fail; that is no longer true.

Shared objects are written but not loaded-shared produces an ET_DYN file. Nothing here has handed one to a dynamic linker, so treat it as written rather than working.

Dynamic linking is x86_64 onlyaarch64 and riscv64 link statically and as PIE, but have no PLT or GOT construction.

Entry point on aarch64 and riscv64With no _start defined, weld's synthetic startup stub is written for x86_64 only. The other two fall back to entering at main, which is wrong without a CRT.

clang AArch64 objects with unwind tablesunsupported AArch64 relocation type 261, which is R_AARCH64_PREL32 in .eh_frame. Building with -fno-asynchronous-unwind-tables gets past it.

Malformed input is bounded, not trustedSymbol and relocation reads in the object readers are bounds-checked, the Mach-O symbol table and the ELF RELA stride are validated against the section they came from, and a reservation derived from a header field cannot be unbounded. A truncated or hostile object is a link error, not a panic or an allocation the size of the file.

Quiet failuresA failed link reports the underlying error rather than a not-implemented placeholder, but some paths still print little. An unknown -e symbol falls back silently, a missing -l is dropped without a message (checked on a static output), and -v needs RUST_LOG=info to show anything.

Interpreter path is assumedWithout --dynamic-linker weld writes the glibc path for the architecture. A musl system needs it passed. The gcc driver passes it anyway; the Lamina driver does not when weld is the linker, which is why a _musl target built through weld still carries the glibc interpreter. Not run on musl.

Archives need an indexarchive has no index; run ranlib to add one. Taken from the source; not run in this pass.
