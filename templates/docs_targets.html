Targets and backends

What a target supports is a list of features, not a score. x86_64 Linux is the reference and has every feature on this page. AArch64, RISC-V 64 and PowerPC64 run most of the test suite under qemu. Each feature they lack is refused by name, not lowered to a guess.

Executed targets

Each row says where its status comes from. The program counts are from the 156 programs in testcases/, compiled and run with the current compiler. CI runs the same programs on Linux, Windows and macOS; the latest CI run that completed had 103 programs and passed on all three. The qemu rows come from a local qemu-user harness that CI does not run.

Integer aggregates in r3–r10, with the overflow split into the parameter save area. Locals sit above that 64 byte area, because printf spills its register arguments there.

What each backend can lower

A backend refuses what it cannot classify. An aggregate it has no rule for is a compile error naming the function, never a silently wrong ABI.

FeatureWhere it worksNotes

Integer scalars, control flow, callseverywhereCommon path. Every published backend lowers it.

Integer aggregates by valuex86_64 aarch64 riscv64 powerpc64A struct or array crossing a boundary by value. WebAssembly and the GPU backends refuse the module instead of guessing a classification. A pointer to one is a scalar and works anywhere.

Float or mixed aggregatesnowhereA struct with a float field is refused everywhere, x86_64 included.

Calls through a pointerx86_64 aarch64 riscv64 powerpc64 wasmWebAssembly builds a function table and calls through call_indirect; a function address is its table index. The GPU backends refuse the module.

Atomics and bit intrinsicsx86_64 aarch64 riscv64 powerpc64Atomic load, store, read-modify-write and fence, and popcount ctlz cttz bswap. The atomics, atomic_orderings and bit_intrinsics programs pass under qemu on the three cross targets. atomic_cmpxchg is not in the IR.

Inline assemblyx86_64 LinuxOther targets refuse the module. The AArch64, RISC-V and PowerPC64 backends each name themselves in the refusal.

Defining a variadic functionx86_64 Linux (System V)Other targets refuse va_start by name. Win64 refuses it too: variadic arguments are not yet supported on Windows x64.

Direct binary emissionx86_64 aarch64The AArch64 encoder in ras has no case for IntConvert or Copy. The default path assembles text with an assembler and does not use it. x86_64 encoder coverage was not checked in this pass.

JIT into executable memoryx86_64, nightly buildThe in-memory path encodes single-block functions. --sandbox fails on a multi-block function. Plain --jit falls back to a temporary executable for it. A three-block function and a direct call both ran correctly through --jit in this pass.

Experimental target identifiers

Code generation exists for these. Only wasm32_wasi has been run. The rest emit assembly or WAT for some programs and were not executed.

ArchitectureIdentifiersNotes

AArch64aarch64_windowsEmits assembly for programs that use no writebyte. A program that uses it is refused: there is no Windows implementation. ras writes no COFF for AArch64, so the object path refuses too. Not run.

RISC-Vriscv32_unknownEmits assembly for i32-only programs. Any i64 value is refused, because rv32 has no 64-bit general register. ras writes no riscv32 object. Not run. Use riscv64_unknown.

WebAssemblywasm32_unknown wasm64_unknown wasm32_wasiwasm32_wasi runs under wasmtime with no host beyond WASI. Today 103 of 156 programs match their expected output; 36 do not emit, and 17 emit but differ (three of those read stdin, which this run did not feed). It writes its own digits, prints through fd_write and exports _start. wasm32_unknown and wasm64_unknown import env.writebyte from the host, so wasmtime cannot run them alone; wasm64 was not run. wasm64 declares a memory64 memory and indexes it with i64. No aggregates by value. The driver has no wasm64_wasi, and the WASI reason for that is not tested here.

How to read this list

Target parsing, code generation, assembly, and linking are separate stages. A recognized identifier does not promise an end-to-end compiler path.

Driver acceptanceThe command-line parser recognizes more identifiers than this public matrix, including ppc64le_linux and ppc64_unknown. Recognition alone is not a support claim.

Not re-run in this passx86_64_windows and aarch64_macos rest on CI, not on a local run. The x86_64 encoder, the nightly JIT beyond the programs named above, and wasm32_unknown at run time were not checked.

AArch64 binary emissionThe direct encoder covers part of the instruction set and rejects IntConvert and Copy. Assembly workflows do not go through it.

Experimental register allocationGlobal linear-scan and graph-color allocation are not available for every backend. The default allocator remains the practical choice.
