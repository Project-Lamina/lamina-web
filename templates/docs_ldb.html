ldb, the debugger

ldb runs a program under ptrace, stops it at breakpoints and prints backtraces, in place of gdb or lldb. Native Linux x86_64 ELF only. It does a small number of things and refuses the rest by name. Its DWARF reader is its own: gimli is not a dependency, so what ldb can read is a direct test of what Lamina writes.

Install

The crate is lamina-ldb and the binary it installs is ldb. There is no release yet, so it comes from a checkout: cargo install --path ldb, or cargo build --release in it. It needs Rust 1.88. Its only dependencies are libc and log.

Using it

$ ldb <program> [program args...] [-ex <command>]... [-batch]

-ex runs a command before the prompt appears and -batch exits instead of prompting, so a session scripts the way a gdb one does.

$ ldb ./factorial -batch -ex 'break factorial' -ex run -ex bt -ex finish
Reading symbols from ./factorial...
Breakpoint 1 at 0x401037: file recursive_factorial.lamina, line 4.

The lines it prints are lines of the .lamina file, because that is what lamina -g names in the line table. Build with -g or there is nothing to read.

Commands

CommandWhat it does
functionsLists every function with its source file and declaration line, grouped by file.
break <function>Breakpoint past the prologue.
break <file>:<line>Breakpoint on a source line. A line with no code is refused with the nearest lines that have some.
break *0x401037Breakpoint on a raw address.
run, continue, kill, quitStart the inferior, resume it, stop it, leave.
stepOne source line, entering a function that has one.
finishRuns to return and reports the value.
btBacktrace, unwound from .eh_frame.
info argsNames the current frame's parameters. See the refusal below.
info line, info breakpointsThe line for the current address, and the breakpoint table.
delete <n>Removes a breakpoint by number.

What it reads

.debug_info, .debug_abbrev, .debug_line and .debug_str are parsed from scratch: DWARF 2 through 5 for .debug_info and .debug_line, in both the 32- and 64-bit unit formats. .eh_frame CFI is interpreted far enough to unwind x86_64, covering the DW_EH_PE pointer encodings, the non-expression call-frame opcodes and remember_state/restore_state.

Backtraces are CFI-driven and stay correct through recursion. finish reads the return value through the subprogram's DW_AT_type: integers sign- or zero-extended by the declared byte size, bool, pointers, and f32/f64 out of xmm0. Both PIE and non-PIE images work, with the load bias taken from /proc/<pid>/maps.

What it refuses

A parameter with no recorded locationinfo args names the parameter and reports <unavailable>, because Lamina emits no DW_AT_location today and a guessed location would be a silent wrong answer.

A line with no codebreak recursive_factorial.lamina:1 answers Not in the debug info: recursive_factorial.lamina:1 has no code. The nearest lines that do: 4, 8, 11, 12, 13 rather than moving the breakpoint somewhere else.

A form or opcode it cannot readAn unreadable DW_FORM is reported by its code. A DW_CFA_def_cfa_expression reports that ldb has no DWARF expression evaluator. Neither is skipped.

What is not here yet

No next, no up/down/frame, no list, no watchpoints, no conditional or temporary breakpoints, no print of an expression, no reading of locals or globals, no disassembler, no signal-handling policy, no multi-threaded or multi-process inferiors, no core files and no attach. There is no remote protocol: ldb forks the program under PTRACE_TRACEME and drives it with PTRACE_PEEKDATA/POKEDATA, PTRACE_GETREGS and waitpid.

There is no DWARF expression evaluator, which DW_AT_location will need before info args can print a value. .debug_ranges and .debug_rnglists are not read, so a function split into non-contiguous ranges is not found. There is no .debug_lamina section yet; nothing is read before it is written and nothing is written before something reads it.
