Lamina compiler · Reference

IR instructions

Every instruction form the parser accepts, with its operands and result. Read IR language first for the slot model and the lexical rules.

Two shapes

An instruction that produces a value is written %name = op .... One that produces none is written op .... Using the wrong shape is an error. Where an instruction has a suffix, it is written after a dot: add.i64, load.i32. A suffix names the operation's type; conversions take two types, trunc.i64.i8.

Operands are values (%name, a global $name, or a literal) except where a bare label or a bare name is required. Literals are range-checked against the suffix type.

Integer and float arithmetic

InstructionFormMeaning

Binaryadd sub mul div rem and or xor shl shrOperands and result have the suffix type. add sub mul div take floats as well as integers. rem and or xor shl shr are integer-only. div, rem and shr are signed or unsigned according to the suffix type.

Rotaterotl rotrInteger only. Rotate left or right.

NegatenegAny numeric type. Two's complement negation for integers.

Bitwise notnotInteger only.

Bit countspopcount ctlz cttz bswapInteger only. Count set bits, leading zeros, trailing zeros, or byte-swap. Compile on x86_64, aarch64, riscv64, ppc64le and armv7. loongarch64 and riscv32 refuse them by name.

Square rootsqrtf32 and f64 only.

fn @main() -> i64 {
  entry:
    %a = sub.i64 10, 3
    %b = mul.i64 %a, 2
    %c = div.i64 %b, 4
    %d = rem.i64 %c, 3
    %e = and.i64 %d, 7
    %f = or.i64 %e, 8
    %g = xor.i64 %f, 1
    %h = shl.i64 %g, 2
    %i = shr.i64 %h, 1
    %j = neg.i64 %i
    %k = not.i64 %j
    %l = rotl.i64 %k, 3
    %m = popcount.i64 %l
    %n = ctlz.i64 %m
    %o = cttz.i64 %n
    %p = bswap.i64 %o
    ret.i64 %p
}
fn @main() -> i64 {
  entry:
    %x = add.f64 1.5, 2.25
    %r = sqrt.f64 %x
    %y = mul.f64 %r, 2.0
    %z = neg.f64 %y
    %ok = lt.f64 %z, 0.0
    %n = fptoint.f64.i64 %y
    ret.i64 %n
}

Comparison

eq ne gt ge lt le take two operands of the suffix type and produce a bool. Signedness follows the suffix type. A bool is accepted by and and or and by br and select.

fn @main() -> i64 {
  entry:
    %a = eq.i64 1, 1
    %b = ne.i64 1, 2
    %c = ge.i64 3, 2
    %d = le.i64 3, 2
    %e = lt.i64 1, 2
    %f = and.bool %a, %b
    br %f, yes, no
  yes:
    ret.i64 1
  no:
    ret.i64 0
}

Conversions

InstructionFormMeaning

Truncatetrunc.S.DKeeps the low bits. The target must be narrower than the source.

Extendextend.S.DWidens an integer. The source type's signedness picks sign or zero extension. The target must be wider. This is the one widening instruction; there is no separate zero or sign form.

Bit castbitcast.S.DReinterprets the bits. Source and target must be the same size.

Integer to floatinttofp.S.DSource is an integer, target is f32 or f64.

Float to integerfptoint.S.DSource is f32 or f64, target is an integer. Truncates toward zero.

Float to floatfpcast.S.DBetween f32 and f64 only.

fn @main() -> i64 {
  entry:
    %a = add.f64 1.5, 2.25
    %b = sqrt.f64 %a
    %c = fpcast.f64.f32 %b
    %d = fpcast.f32.f64 %c
    %e = fptoint.f64.i64 %d
    %f = inttofp.i64.f64 %e
    %g = trunc.i64.i32 %e
    %h = bitcast.f64.i64 %f
    ret.i64 %e
}
Extend

The widening form is extend.S.D, with the extension chosen by the source type's signedness: %w = extend.i8.i64 %b sign-extends an i8 and zero-extends a u8. zext and sext are rejected, and the error names extend as the replacement.

fn @widen(i8 %b, u8 %c) -> i64 {
entry:
  %w = extend.i8.i64 %b
  %u = extend.u8.u64 %c
  ret.i64 %w
}

Select

%r = select.T cond, a, b returns a when cond is true and b otherwise. cond must be a bool. a and b have type T.

fn @max(i64 %a, i64 %b) -> i64 {
  entry:
    %a_wins = gt.i64 %a, %b
    %r = select.i64 %a_wins, %a, %b
    ret.i64 %r
}

fn @main() -> i64 {
  entry:
    %r = call @max(3, 9)
    ret.i64 %r
}

Memory

InstructionFormMeaning

Stack allocation%p = stackalloc.T or stackalloc.T align nReserves storage for one T (or a named type or array) in the current frame, and returns its ptr. It is released when the function returns. align n sets the alignment and must be a power of two.

Load%v = load.T ptrReads a T from memory.

Storestore.T ptr, valueWrites a T. The value must have type T.

Volatile%v = volatile load.T ptr, volatile store.T ptr, valueSame as load and store, with the access kept in program order and not elided. Only these two may be volatile.

Element address%p = getelem.T ptr, indexAddress of element index of an array or of a sequence of T. The index is scaled by the size of T, so the suffix is required. The index may be a value of any integer type.

Field address%p = getfieldptr.!Name ptr, NAddress of field N of the named struct. The suffix names the layout type and is required. N is an integer literal.

Pointer to integer%n = ptrtoint.T ptrConverts an address to an integer of type T.

Integer to pointer%p = inttoptr.T valueConverts an integer of type T to a pointer.

global $tab: [3 x i64] = [10, 20, 30]

fn @main() -> i64 {
  entry:
    %cell = stackalloc.i64 align 16
    store.i64 %cell, 1
    %arr = stackalloc.[4 x i32]
    %e = getelem.i32 %arr, 2
    store.i32 %e, 9
    %t = getelem.i64 $tab, 1
    %tv = load.i64 %t
    volatile store.i64 %cell, 6
    %w = volatile load.i64 %cell
    ret.i64 %w
}
Field addresses

getfieldptr takes the layout type in its suffix, and the suffix is required, so the field offset comes from the named struct: getfieldptr.!Pair %p, 1 is field 1 of !Pair. The bare form getfieldptr %p, 1 is a parse error: getfieldptr needs its struct layout as a suffix, because the field offset depends on it. The index must be a literal.

type !Pair = struct { a: i32, b: i64 }

fn @set_b(ptr %p) -> void {
  entry:
    %f = getfieldptr.!Pair %p, 1
    store.i64 %f, 5
    ret.void
}

Vectors

A vector is a type, not a second family of operations. An opcode already carries its type as a suffix, so add.<4 x i32> is the same add as add.i64. There is no simd_add and no parallel opcode table. The type page says where a <N x T> may appear; the short version is that it may be an instruction suffix and the type of a value, and nothing else.

InstructionFormMeaning

Element-wiseadd sub mul and or xorBoth operands and the result have the suffix type. div, rem, rotl and rotr have no vector form on any target here and are refused by name.

Shift%c = shl.<4 x i32> %a, %nThe type of the count says which shift it is. A scalar or a literal count is one count for every lane. A count vector of the same shape is one count per lane. Both readings are correct on their face, which is why the type decides rather than a second opcode. The lane type picks logical against arithmetic the way it does for scalars: shr.<4 x u32> is logical, shr.<4 x i32> arithmetic. Float lanes are refused. A count of the lane width or more gives zero, or the sign for an arithmetic right shift, on every target and in both forms.

Splat%v = splat.<4 x i32> 7One scalar into every lane.

Extract a lane%x = extractlane.<4 x i32> %v, 2Result is a scalar of the lane type. The index is part of the instruction, not an operand; writing %i there is a parse error naming the reason. A lane chosen at run time is a different and far more expensive operation, and accepting one silently would be a performance cliff nobody can see.

Insert a lane%w = insertlane.<4 x i32> %v, 9, 1Result is a vector. The index is constant, as above.

Shuffle%s = shuffle.<4 x i32> %a, %b, [0, 5, 2, 7]The mask holds one entry per result lane and indexes the lanes of %a followed by those of %b, so entries run from 0 to 2N-1. The mask is constant. MIR has no shuffle opcode, so this expands to a zero splat and an extract-insert pair per lane: correct everywhere, and not what a single pshufd would cost.

Memory%v = load.<4 x i32> %p, store.<4 x i32> %p, %vThe ordinary load and store with a vector suffix. The pointer is a plain ptr, so nothing about the vector reaches a declaration.

There are no vector comparisons, no reductions, no vector select, no masks, no gather or scatter and no conversions between vector types. x86_64, AArch64 and WebAssembly lower 128-bit vectors; every other backend refuses by name. 256-bit vectors parse and validate and no backend lowers them. The target matrix has the per-backend holes.

Atomics and fences

Atomic operations are available on x86_64, aarch64, riscv64 and ppc64le. atomic_cmpxchg.T ptr, expected, desired, success, failure yields one result, the value that was in memory before the operation. The exchange happened exactly when that value equals expected. Atomic operations take an integer or ptr type. Orderings are relaxed, acquire, release, acqrel and seqcst. atomic_load rejects release and acqrel. atomic_store rejects acquire and acqrel.

InstructionFormMeaning

Atomic load%v = atomic_load.T ptr, ORDReturns the value.

Atomic storeatomic_store.T ptr, value, ORDStores the value. No result.

Read-modify-write%old = atomic_add atomic_sub atomic_and atomic_or atomic_xor atomic_exchange .T ptr, value, ORDApplies the operation and returns the previous value. Spelled with a dot before the type: atomic_add.i64.

Fencefence ORDNo operands and no result.

fn @main() -> i64 {
  entry:
    %cell = stackalloc.i64
    store.i64 %cell, 1
    %old = atomic_add.i64 %cell, 3, seqcst
    %now = atomic_load.i64 %cell, acquire
    atomic_store.i64 %cell, 7, release
    %x = atomic_exchange.i64 %cell, 100, acqrel
    fence seqcst
    ret.i64 %now
}

Calls and function addresses

InstructionFormMeaning

Callcall @f(args) or %r = call @f(args)Direct call. Each argument is a value, optionally preceded by its type: call @f(7) or call @f(i64 7). A typed argument must match the parameter exactly. The result is typed by the callee; a call to a void function has no result.

Function address%p = funcaddr @fThe address of a function, as a ptr.

Indirect call%r = callptr.T ptr(args) or callptr.void ptr(args)Calls through a pointer. The suffix is the return type and is required. Every argument must carry its type. A bare ... may appear once, to mark the variadic tail of a call to a variadic function. The x86_64 backend does not yet act on it; see the ABI page before passing float arguments through a pointer.

fn @add(i64 %a, i64 %b) -> i64 {
  entry:
    %s = add.i64 %a, %b
    ret.i64 %s
}

fn @main() -> i64 {
  entry:
    %f = funcaddr @add
    %r = callptr.i64 %f(i64 40, i64 2)
    %s = call @add(i64 %r, 0)
    ret.i64 %s
}

A call to a function the module does not define needs an @extern declaration first. Calling an undeclared name is an error.

Inline assembly

%r = asm.T "template", operands, clobber(names) runs the template as x86_64 assembly and gives the result type T. asm.void "template", clobber(names) has no result. In the template, $0, $1 and so on name the operands in order, and $$ is a literal dollar sign, so $$7 is the immediate 7 in AT&T syntax.

Inputin(reg) %v takes any register. in(rcx) %v takes that register.

Outputout(reg) takes any register and out(eax) a named one. The result is the value of that register after the template runs.

ClobbersName every register the template changes, plus memory if it writes memory and flags if it sets the flags.

Targetsx86_64 Linux only. The AArch64, RISC-V and PowerPC64 backends refuse the module and name themselves in the error.

fn @main() -> i64 {
entry:
  %t = asm.i64 "movq $$7, $0", out(reg)
  ret.i64 %t
}

Control flow

InstructionFormMeaning

Branchbr cond, then, elsecond must be a bool value. Labels are bare.

Jumpjmp labelUnconditional.

Switchswitch.T value, default, [literal, label], ...Dispatches on an integer value of type T. Case literals are checked against T. The discriminant must be a value; a literal discriminant is refused.

Returnret.T value or ret.voidThe value must have the function's return type.

UnreachableunreachableMarks a block that must not be reached. It ends the block.

fn @label_for(i32 %k) -> i64 {
  entry:
    switch.i32 %k, other, [0, zero], [7, seven]
  zero:
    ret.i64 0
  seven:
    ret.i64 7
  other:
    ret.i64 1
}

fn @main() -> i64 {
  entry:
    %k = add.i32 3, 4
    %r = call @label_for(%k)
    ret.i64 %r
}

Input and output

These four instructions move bytes to and from the process's standard streams. The assignment form binds the result to a name. The statement form, used when the result is not needed, takes a trailing bare name instead, which defines that name for the rest of the function. Each result is an integer. The full contract, including the end-of-input and error values, is on Output and I/O.

InstructionAssignment formStatement form

Write%n = write %buf, sizewrite %buf, size, name

Read%n = read %buf, sizeread %buf, size, name

Write byte%n = writebyte valuewritebyte value, name

Read byte%n = readbytereadbyte name

fn @main() -> i64 {
  entry:
    %p = stackalloc.[4 x i8]
    store.i8 %p, 79
    %n = write %p, 1
    %m = writebyte 10
    write %p, 1, k
    writebyte 10, j
    %r = read %p, 1
    %b = readbyte
    ret.i64 %n
}

readbyte takes no operand, so %b = readbyte %x is an error: %x starts the next statement.

Removed spellings

These spellings are rejected with a hint that names their replacement.

printRemoved. Write bytes with writebyte, or call a printf-style function declared with @extern.

heapalloc, heapfreeRemoved. Declare @extern fn @malloc(i64 %n) -> ptr and @extern fn @free(ptr %p) -> void, then call them.

memcpy, memmove, memsetRemoved. Declare them with @extern and call them. They were always calls.

zext.S.D, sext.S.DReplaced by extend.S.D, chosen by the source signedness.

alloc, getfield, getelementptr, extract, tupleRemoved. Use stackalloc, getfieldptr with a layout type, getelem with a type suffix, and named structs.

sitofp, uitofp, fptosi, fptoui, fpext, fptruncReplaced by inttofp, fptoint and fpcast.

charRemoved type. Use i8 or u8.

Variadic bodies (va_start, va_arg, va_end, va_copy) are written on x86_64 System V only. Other targets refuse them by name. A Lamina function can be variadic on that target. tailcall does not exist. Two-result instructions do not exist.
