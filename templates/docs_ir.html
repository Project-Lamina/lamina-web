IR language

Lamina IR is a text format for typed functions made of named blocks. This page covers the model, the lexical rules, types, declarations and annotations. Every instruction is in IR instructions. What the syntax on this page means — what each operation computes, what traps, and which targets refuse it — is stated clause by clause in the IR semantics, which is normative where this page and it disagree.

This is not SSA

If you come from LLVM, read this section first. The text has no SSA form and no merge instruction. A name such as %total is a mutable slot for the whole function. Its first assignment defines it and fixes its type. Later assignments, on any path, must give a value of that same type.

A read of a name returns the value of its most recent assignment on the path the program actually took. Where two paths join, you assign the same name on each path and read it after the join.

fn @pick(i64 %n) -> i64 {
  entry:
    %big = gt.i64 %n, 2
    br %big, wide, narrow
  wide:
    %width = add.i64 %n, 100
    jmp done
  narrow:
    %width = add.i64 %n, 1
    jmp done
  done:
    ret.i64 %width
}

fn @main() -> i64 {
  entry:
    %r = call @pick(1)
    ret.i64 %r
}

The loop below is the same idea over many iterations. %i is assigned in entry and again in body. Each read sees the latest assignment on the path that ran. The program returns 10.

fn @main() -> i64 {
  entry:
    %i = add.i64 0, 0
    jmp head
  head:
    %done = ge.i64 %i, 10
    br %done, exit, body
  body:
    %i = add.i64 %i, 1
    jmp head
  exit:
    ret.i64 %i
}

Two rules follow from the slot model, and the compiler enforces both.

Definite assignmentEvery read must be definitely assigned. Every path from the entry block to a read must assign the name first. If one branch of a join never assigns the name, a read after the join is rejected, even when the other branch assigns it.

One type per nameA name keeps the type of its first definition. Reassigning it with a different type is a validation error. Reassigning with the same type is allowed.

Why

A slot with one type and explicit assignments says exactly what a merge does. It needs no separate merge instruction, and a reader can see each value's origin by reading the path.

Lexical rules

CommentsA # starts a comment that runs to the end of the line. // is not a comment.

NamesA name starts with a letter or underscore, then letters, digits or underscores. Dots and dashes are not allowed. A keyword is a legal name after a sigil, so %ret and @add are valid.

Sigils%name is a local or parameter. $name is a global. @name is a function. !Name is a named type. Block labels and the names given to statement-form I/O are bare.

IntegersDecimal only, with an optional - attached to the digits: -5. No hex, underscores or leading +. A literal must fit its type. add.i8 %x, 300 is an error, and so is ret.i8 300. This is checked in every typed position: operands, return values, stores, call arguments, switch cases, and global and array initializers.

FloatsWrite a digit on each side of the dot: 1.5, -0.0, 2.5e-3. Under a float type you may also write 1e3.

Booleanstrue and false, lowercase only.

StringsDouble-quoted. Escapes \n, \t, \0, \xHH and \" are decoded. Strings are valid only as initializers of [N x i8] globals. A string argument to a call is rejected; take the address of a global with getelem.i8 $name, 0.

Types

Signed integersi8 i16 i32 i64 i128Two's complement. i128 arithmetic works on the 64-bit targets; 128-bit division and conversions call compiler-rt routines (see Runtime and libc). The 32-bit machine targets refuse i128 outright, as a local value and not only at a boundary: names a 128-bit integer on a 32-bit target: that takes four registers, and only pairs are split. Globals of 128-bit type are not lowered yet.

There is no char and no tuple. Use i8 for a signed byte or u8 for an unsigned one. Use a struct with named fields where a tuple would go.

Vectors are a suffix type

A lane type is one of i8 i16 i32 i64, their unsigned forms, f32 and f64. bool, ptr and the 128-bit integers have no lane form. The total width, lanes times lane bits, must be 128 or 256; anything else is refused as no vector register width. Only 128 is lowered by any backend today.

A vector type may not appear in a declaration. Not a function parameter, not a return type, not a global, not a struct field, not a stackalloc. Validation refuses each by name, and type_layout deliberately gives a vector no size and no alignment, so any path that would need one fails rather than invent it. The reason is the ABI: every target classifies a vector at a call boundary differently, no backend implements that classification, and admitting the syntax would admit a shape the register allocator refuses.

What is left is enough to write a kernel. A vector enters a function through load, through splat, or lane by lane through insertlane; it leaves through store or extractlane. A [4 x i32] global and a load.<4 x i32> reach the same bytes a vector global would. A helper that works on vectors takes a pointer. See the instruction reference for the operations.

Declarations

A module is a sequence of type declarations, globals and functions, in any order. Names must be unique within their kind.

Named types

type !Pair = struct { a: i32, b: i64 }
type !Row = [4 x i32]

fn @second(ptr %p) -> i64 {
  entry:
    %v = load.i64 %p
    ret.i64 %v
}

fn @main() -> i64 {
  entry:
    %slot = stackalloc.!Pair
    %r = stackalloc.!Row
    ret.i64 0
}

A struct needs at least one field, field names must be unique, and a trailing comma is allowed. Unnamed struct fields are not allowed, and one named type cannot be an alias of another.

Globals

global $name: T declares a global with no initializer. global $name: T = value gives it one. An initializer must be a literal: a number, true, a string for [N x i8], a list [a, b] for an array, or {a, b} for a struct.

type !Pair = struct { a: i32, b: i64 }

global $counter: i64 = 41
global $buf: [64 x i8]
global $squares: [6 x i64] = [0, 1, 4, 9, 16, 25]
global $msg: [4 x i8] = "hi\n"
global $origin: !Pair = {1, 2}
global $ratio: f64 = 1.5
global $flag: bool = true

fn @main() -> i64 {
  entry:
    %c = load.i64 $counter
    store.i64 $counter, 42
    ret.i64 %c
}
  • A string initializer includes its NUL terminator in the count. [3 x i8] = "ab" is valid; [2 x i8] = "ab" is not.
  • A list may be shorter than its array, but not longer.
  • @export before global makes the symbol visible outside the module. @align(n) before global sets its alignment.

Functions

A function is a name, typed parameters, a return type and one or more blocks. Each parameter needs a name. Execution starts at the first block, whatever its label. A block is a label, a colon, and instructions. The last instruction of each block is a terminator: ret, jmp, br, switch or unreachable. No instruction may follow a terminator.

fn @clamp(i64 %x, i64 %lo, i64 %hi) -> i64 {
  entry:
    %below = lt.i64 %x, %lo
    br %below, low, check_high
  low:
    ret.i64 %lo
  check_high:
    %above = gt.i64 %x, %hi
    br %above, high, inside
  high:
    ret.i64 %hi
  inside:
    ret.i64 %x
}

fn @main() -> i64 {
  entry:
    %r = call @clamp(50, 0, 10)
    ret.i64 %r
}

External functions

A function the module does not define is declared with @extern and no body. Giving it a body is an error: drop the body to declare the function, or drop @extern to define it here. A declaration ending in ... is variadic, and so is a function with a body. On x86_64 Linux the body reads the extra arguments with va_start and va_arg; the other targets refuse va_start by name. The ... must be the last parameter.

@extern
fn @printf(ptr %fmt, ...) -> i32

global $fmt: [7 x i8] = "%d %f\n"

fn @main() -> i64 {
  entry:
    %f = getelem.i8 $fmt, 0
    %r = call @printf(ptr %f, i32 42, f64 2.5)
    ret.i64 0
}

The compiler adds no libc of its own. Whatever an @extern name resolves to is found at link time. See Runtime and libc.

Annotations

Annotations go on the line before the declaration they modify. Several may stack. Conflicting or repeated annotations are errors.

AnnotationApplies toEffect
@exportfn, globalExports the symbol. Cannot be combined with internal, private or @extern.
@externfnDeclaration only. A function carrying it may not have a body; one that does is rejected. Supports ....
@inline @noinlinefnInlining hints. Cannot be combined with each other.
@hot @coldfnPlacement and optimization hints. Cannot be combined with each other.
@noreturnfnThe function does not return.
@purefnOptimization hints about side effects.
@internal @private @hidden @protectedfnSymbol visibility. Any two of these conflict.
@weakfnWeak symbol binding.
@section("name")fnPlaces the function in a named section. The name must be non-empty and contain no backslash. On Mach-O only .text.<name> is accepted, mapped to __TEXT,__<name>, and the name is limited to 14 characters of [A-Za-z0-9_]; anything else is refused.
@align(n)fn, globaln is a power of two. On a global it sets the alignment of the object.
@kernelfnGPU kernel. Refused on a CPU target with GPU kernels and intrinsics require a GPU target.
@pic @piemoduleNightly only. Changes code generation on x86_64 Linux: external addresses are loaded through the GOT. @pic and @pie cannot be combined with each other or repeated. They are not available in the default build.

Nightly build only. The default build rejects @pie.

@pie
@section(".text.hot")
@align(64)
fn @main() -> i64 {
  entry:
    ret.i64 0
}

The @optimize_speed, @optimize_size, @debug, @strip and @target_triple annotations were removed. Use --opt-level, -g, the strip tool and --target instead. @const was removed too: use @pure.
