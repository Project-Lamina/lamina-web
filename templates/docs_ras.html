ras · Assembler

ras, the assembler

ras turns assembly into a relocatable object, in place of GNU as. It is what Lamina uses with --assembler ras, and a C toolchain can call it too. It is not a complete as: the list of what it does not take is near the bottom, and it is short enough to read.

Install

The crate is lamina-ras; the binary it installs is ras. The newest release{{#if ras_version}}, {{ras_version}},{{/if}} is not the version this page describes, so cargo install lamina-ras does not get it.

The source this page describes needs Rust 1.88 or newer. It uses let chains, and Rust 1.87 refuses it. Its manifest patches lamina-platform, lamina-mir and lamina-codegen to a sibling lamina checkout, so build it from a checkout that has both directories side by side. Build it with cargo install --path ras from there.

The encoder feature adds the MIR-to-machine-code path used for JIT. Assembling text to an object does not need it, so the default build is enough for use as an assembler.

Not checked here

Installing the published release from crates.io was not run.

With the Lamina driver

$ lamina app.lamina --assembler ras
$ lamina app.lamina --assembler ras -c weld

In place of GNU as

ras reads argv[0]. Invoked under the name as, or any name ending in -as, it switches to GNU-compatible argument parsing and accepts the flags a compiler driver passes. So the way to put it in a C build is a symlink and -B:

$ mkdir -p toolchain
$ ln -sf "$(command -v ras)" toolchain/as
$ gcc -B"$PWD/toolchain/" hello.c -O2 -o hello

This works with gcc 13 on x86_64 Linux and prints hello 42 for a test program.

clang does not work with ras yet. clang 18 writes callq in its assembly, and ras rejects it with Unsupported instruction: callq. Passing -fno-integrated-as is still needed to make clang call an external assembler, but the assembler then fails on its output.

Under the name as the flags a driver sends are taken or ignored as GNU takes them: -o, -I, -J and -arch take a value, -L keeps local symbols, and --64 --32 -n -q -s -g -Z -K -Q -k -v -V -w -d along with -march=, -mcpu=, -mabi=, -mtune= and the --gdwarf- forms are accepted and ignored.

Native mode

Invoked as ras, the argument set is its own and much smaller.

OptionArgumentBehavior

-o, --output<file>Object to write. Defaults to a.out.

--target<arch_os>Architecture and object format. Defaults to the host.

-v, --verbose-Log at info level. RUST_LOG also works.

-L, --keep-locals-Keep local symbols in the symbol table.

--64, --32, --x32-Accepted and ignored, so a driver that passes them does not fail.

x86-64 vector coverage

This is the part of the x86-64 encoder most likely to decide whether a build works, so it is written out rather than summarized. Each encoding is checked against GNU as by assembling the same source with both and comparing the .text bytes and the relocation list. The comparison normalizes one thing and only one: which multi-byte form an assembler pads with, since that differs between binutils releases while where the padding starts and ends does not. A second set of tests pins exact bytes per instruction form, so a regression cannot hide behind a reference assembler that moved at the same time.

SSE, SSE2, SSE3, SSSE3The packed and scalar float sets, the full packed-integer set, the horizontal and duplicate forms, pshufb, palignr, the sign and absolute-value ops, and every cvt and cvtt form.

SSE4.1, SSE4.2The blends, dpps/dppd, insertps/extractps, pmulld/pmuldq, all twelve pmovsx/pmovzx forms, ptest, the rounds, the byte and doubleword lane transfers, crc32, the string compares and popcnt.

AVX, AVX2The VEX counterparts of the above over both xmm and ymm: arithmetic, the integer ops, the shuffles and blends, the moves, the broadcasts, the 128-bit insert and extract, the permutes, the masked moves, and vzeroupper.

FMA3The mnemonic is decomposed rather than tabulated, so vfmadd, vfmsub, vfnmadd and vfnmsub across the 132, 213 and 231 operand orders and the ps, pd, ss and sd widths are all covered, as are vfmaddsub and vfmsubadd in their packed forms. The combinations that do not exist — a scalar maddsub, a negated maddsub — are rejected. FMA4, the four-operand AMD form, is not implemented.

Variable vector shiftsvpsllvd, vpsllvq, vpsrlvd, vpsrlvq and vpsravd. vpsravq is AVX-512 only and is correctly absent.

Other extensionsAES-NI, PCLMULQDQ, the BMI2 shifts, LZCNT and TZCNT, a working x87 subset, and the TLS relocation syntaxes.

Three gaps, stated because an assembler that silently miscodes is worse than one that refuses:

AVX-512Effectively absent. There is an EVEX prefix and exactly one mnemonic that uses it, vpmullq, register operands only. There is no %zmm register, no mask register, and no {z}, broadcast or rounding decorator.

VSIB gathersNo vgather or vpgather form, and the memory-operand parser has no vector-index path, so a VSIB address cannot be written at all.

MMXNo %mm registers, no emms, and no NP-prefixed forms of the packed ops. Every p opcode is the xmm SSE2 encoding.

Where it is not a drop-in

Worth knowing before pointing a build at it.

gcc -g failsgcc emits its own .debug_* sections under -g, and ras refuses to add .loc line tables beside them: Object file error: source defines .debug_* sections; ras cannot add .loc DWARF beside them. Build without -g. For debug output, lamina -g --assembler ras works, and so does --assembler gas.

Cross-assembly needs --targetUnder the name as there is no way to pass it, and a prefixed name like aarch64-linux-gnu-as does not imply the architecture. GNU mode always assembles for the host.

No stdin in GNU modeUnder the name as, as - and a redirect both fail with missing input .s file. Native ras reads stdin when it is redirected, but ras - is refused with Unknown option: -.

Missing directivesNo .macro, .org, .fill, .include, .incbin, .intel_syntax, .octa, .weakref, .symver or .lcomm. Each is refused by name rather than ignored. .protected and .internal are accepted.

Comment and separator syntax/* */ comments are not stripped and ; does not separate statements. Hand-written assembly using either needs editing.

CFI is x86_64 and aarch64 onlyOther targets report CFI unsupported for target. The .cfi_sections directive was not tested in this pass.
