ras · Assembler

ras, the assembler

ras turns assembly into a relocatable object, in place of GNU as. It is what Lamina uses with --assembler ras, and a C toolchain can call it too. It is not a complete as: the list of what it does not take is near the bottom, and it is short enough to read.

Install

The crate is lamina-ras; the binary it installs is ras. The newest release on crates.io is 0.1.5, which is not the version this page describes. cargo install lamina-ras gets 0.1.5.

The 0.2.0 source needs Rust 1.88 or newer. It uses let chains, and Rust 1.87 refuses it. Its manifest patches lamina-platform, lamina-mir and lamina-codegen to a sibling lamina checkout, so build it from a checkout that has both directories side by side. Build it with cargo install --path ras from there.

The encoder feature adds the MIR-to-machine-code path used for JIT. Assembling text to an object does not need it, so the default build is enough for use as an assembler.

Not checked here

Installing 0.1.5 from crates.io was not run; the version above comes from cargo info.

With the Lamina driver

$ lamina app.lamina --assembler ras
$ lamina app.lamina --assembler ras -c weld

In place of GNU as

ras reads argv[0]. Invoked under the name as, or any name ending in -as, it switches to GNU-compatible argument parsing and accepts the flags a compiler driver passes. So the way to put it in a C build is a symlink and -B:

$ mkdir -p toolchain
$ ln -sf "$(command -v ras)" toolchain/as
$ gcc -B"$PWD/toolchain/" hello.c -O2 -o hello

This works with gcc 13 on x86_64 Linux and prints hello 42 for a test program.

clang does not work with ras yet. clang 18 writes callq in its assembly, and ras rejects it with Unsupported instruction: callq. Passing -fno-integrated-as is still needed to make clang call an external assembler, but the assembler then fails on its output.

Under the name as the flags a driver sends are taken or ignored as GNU takes them: -o, -I, -J and -arch take a value, -L keeps local symbols, and --64 --32 -n -q -s -g -Z -K -Q -k -v -V -w -d along with -march=, -mcpu=, -mabi=, -mtune= and the --gdwarf- forms are accepted and ignored.

Native mode

Invoked as ras, the argument set is its own and much smaller.

OptionArgumentBehavior

-o, --output<file>Object to write. Defaults to a.out.

--target<arch_os>Architecture and object format. Defaults to the host.

-v, --verbose-Log at info level. RUST_LOG also works.

-L, --keep-locals-Keep local symbols in the symbol table.

--64, --32, --x32-Accepted and ignored, so a driver that passes them does not fail.

--version, -h, --help-Print the version or the usage block.

Architectures and formats

FormatWritten forNotes

ELF64x86_64 aarch64 riscv64Linux and the BSDs, plus Redox, Orbis and Prospero. ELF64 little-endian only.

Mach-Ox86_64 arm64macOS. Any other architecture is refused by name.

COFFx86_64Windows. aarch64_windows is refused.

x86_64 input is AT&T syntax. riscv32_linux is refused at object output: riscv32 object output is not implemented: ras writes ELF64 only. The bare riscv32_unknown and riscv64_unknown names are refused because they name no operating system; use the _linux names.

Where it is not a drop-in

Worth knowing before pointing a build at it.

gcc -g failsDebug builds emit .loc, and ras has no line-table directive. Unsupported directive: .loc. Build without -g, or use --assembler gas or clang for debug output.

Cross-assembly needs --targetUnder the name as there is no way to pass it, and a prefixed name like aarch64-linux-gnu-as does not imply the architecture. GNU mode always assembles for the host.

No stdin in GNU modeUnder the name as, as - and a redirect both fail with missing input .s file. Native ras reads stdin when it is redirected, but ras - is refused with Unknown option: -.

Missing directivesNo .macro, .org, .fill, .include, .incbin, .intel_syntax, .octa, .weakref, .symver or .lcomm. Each is refused by name rather than ignored. .protected and .internal are accepted.

Comment and separator syntax/* */ comments are not stripped and ; does not separate statements. Hand-written assembly using either needs editing.

CFI is x86_64 and aarch64 onlyOther targets report CFI unsupported for target. The .cfi_sections directive was not tested in this pass.
