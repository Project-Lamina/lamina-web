Writing output

There are two ways to print from Lamina, and print is neither of them. Call libc the way C does, or write bytes yourself and depend on nothing.

print is not one of them

print exists so the compiler's own testcases can show a number without a runtime. It loads a format string and calls printf, so it quietly links libc into a program that may not want it. It is a debugging aid, it is being retired, and application code must not use it.

Through libc

Declare the function with @extern and call it. A declaration ending in ... is variadic, so this is how printf and its relatives are reached. Arguments past the named ones follow the C promotion rules: an f32 widens to f64 on the way out.

@extern
fn @printf(ptr %fmt, ...) -> i32

global $fmt: [8 x i8] = "%d %s\n"
global $who: [7 x i8] = "lamina"

fn @main() -> i64 {
entry:
  %f = getelem.i8 $fmt, 0
  %w = getelem.i8 $who, 0
  %r = call @printf(%f, 42, %w)
  ret.i64 0
}

A global array is not a pointer, so getelem.i8 $fmt, 0 takes the address of its first byte. That is the value printf wants.

Calling through a function pointer works too, and needs the ... marker at the call site, because an indirect call has no declaration to read it from.

%p = funcaddr @printf
%r = callptr.i32 %p(ptr %f, ..., i32 42)

Freestanding

writebyte sends one byte to stdout and needs no libc, no runtime and no linked library. It is the portable choice, and it works on every target including WebAssembly, where it lowers to fd_write.

fn @put_digit(i64 %n) -> i64 {
entry:
  %ascii = add.i64 %n, 48
  %w = writebyte %ascii
  ret.i64 0
}

fn @put_u64(i64 %n) -> i64 {
entry:
  %small = lt.i64 %n, 10
  br %small, last, more
more:
  %hi = div.i64 %n, 10
  %lo = rem.i64 %n, 10
  %r = call @put_u64(%hi)
  %d = call @put_digit(%lo)
  ret.i64 0
last:
  %e = call @put_digit(%n)
  ret.i64 0
}

fn @main() -> i64 {
entry:
  %a = call @put_u64(31415)
  %nl = writebyte 10
  ret.i64 0
}

That prints 31415. Formatting a number is the frontend's job, not the IR's, which is why there is no instruction for it.

Raw bytes

InstructionFormDoes

writebyte%r = writebyte %valueWrites the low 8 bits to stdout. One byte, one syscall.

readbyte%r = readbyteReads one byte from stdin. Returns the byte, or 0 at end of input.

write%r = write %ptr, %sizeWrites %size bytes from %ptr to stdout.

read%r = read %ptr, %sizeReads up to %size bytes from stdin into %ptr.

Each returns the count moved, or a negative errno. There is no buffering: these are syscalls, not a stdio layer.
