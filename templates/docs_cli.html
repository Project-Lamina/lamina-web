Lamina compiler · Reference

Compiler driver

The lamina binary compiles one IR file. It writes an executable, assembly or LUMIR, selects a target, and chooses the assembler and linker. Options are listed here as lamina --help prints them.

$ lamina <input.lamina> [options]

Output

OptionArgumentBehavior
-o, --output<file>Name of the executable. Default: the input name without its extension.
--emit-asm-Write an assembly file and stop before assembling and linking.
--emit-mir-Write a .lumir file next to the input and stop. See LUMIR.
--jit-Compile the module and run it in the current process; the process exits with the value main returns. Works in a default build. If in-memory compilation fails it falls back to building and running a temporary executable, which is reported under --verbose. It refuses what it cannot run rather than running something else: a --target that is not the host, a @kernel function, which needs a GPU, and a module with no unambiguous entry point.
--sandbox-Run the JIT in a sandbox. Requires --jit. The sandboxed path encodes single-block functions only and does not fall back to an executable: a multi-block function fails with Sandbox compilation failed.
-g-Emit assembler .file and .loc directives, and minimal ELF DWARF. Works with --assembler ras (the default) and --assembler gas.
-v, --verbose-Print more about each stage.
-h, --help-Print the usage text.
--version-Print the compiler version.

Target and optimization

OptionArgumentBehavior
--target<arch_os[_env]>Target for code generation, such as x86_64_linux or x86_64_linux_musl. Default: the host, and detection fails with a message naming the architecture or operating system when there is no backend for it rather than guessing one. A sub-architecture may be named in place of the bare architecture: rv64gc, armv7a-neon, aarch64v8.2, ppc64le-power9. An environment may follow the operating system: gnu, musl, lamina, eabi, eabihf, none. lamina names Lamina’s own C library, which is not implemented; it parses on x86_64 and aarch64 and the link refuses it by name. Left out, each target declares its own; a combination an architecture does not accept is refused by name. See Targets and backends.
--cpu-level<v1|v2|v3|v4>The x86-64 level the output may use. Default: v2. At v1, popcount compiles to a SWAR sequence, because the POPCNT instruction belongs to v2. It also decides what the vector path may emit: lane access of byte, doubleword and quadword lanes needs v2, and a per-lane vector shift needs the AVX2 of v3. Only for x86_64 targets; other targets refuse the flag. The default is checked against the host when the build is for this machine: a defaulted level the host cannot execute is refused, because code the compiler chose that the machine cannot run is a mistake rather than an intent. An explicit --cpu-level names a machine the operator chose and is taken as written.
--opt-level<0-3>Optimization level for the LUMIR optimizer. Default: 1. Experimental.
--regalloc<method>incremental, linear or graph. The default follows what the backend implements rather than what the architecture is called: a backend with a global allocation pass takes linear at level 1 and above, and one without takes incremental at every level. x86_64, aarch64, riscv32, riscv64, ppc64le and ppc64 have the pass. Picking it this way rather than by name improved aarch64 and riscv64 output substantially, because they had the pass and were not getting it.
--mcpu<gpu>AMDGPU processor: gfx900 or gfx1200. Default: gfx1200.
-j, --jobs<n>Number of code generation threads. Default: the available cores minus two.

Assembler and linker

OptionArgumentBehavior
--assembler<name>Assembler to run: ras, gas or clang.
-c, --compiler<name>Toolchain: gnu, clang, msvc or lamina. Or a linker alone: ld, lld, mold, weld, link or cl.
-Wl,<flag>-Pass flags to the linker. Separate several with commas.
-Wa,<flag>-Pass flags to the assembler. Separate several with commas.
 
$ lamina app.lamina --assembler ras -c weld -o app
$ lamina app.lamina --assembler gas -c ld -o app
$ lamina app.lamina --emit-mir --opt-level 3 --regalloc graph

A linker named with -c must be on PATH. Without weld on PATH, the driver fails with Failed to spawn linker 'weld'.

-c names a linker as well as a toolchain. The option name is historical: it chooses the linker, and --assembler chooses the assembler.
