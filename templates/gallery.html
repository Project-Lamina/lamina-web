Languages and projects whose own source hands code generation to Lamina. A project is listed when its code calls Lamina to produce the output that users run. The call has to be in a public repository you can read, so every entry here can be checked. Being listed says nothing about how finished a project is or how many people use it.

Frontends

Projects that compile their own source language through Lamina.

Language, early development

Nukleus

A programming language implemented in Rust. Its README marks it as in early development. The compiler has its own lexer and AST stage, then lowers the program to Lamina IR.

Lamina is the default AOT backend, and the driver selects it unless told otherwise. The codegen crate calls compile_lamina_ir_to_assembly, or compile_lamina_ir_to_target_assembly when a target is named. Cranelift is available only behind an optional jit feature.

Demonstrations

A complete compiler for a small language, written to show the Lamina pipeline from source to executable. It is a real code path and a useful reference, but it is an example of use, not a production frontend.

Demonstration, Brainfuck

brainfuck-lamina

A Brainfuck compiler. It parses the source to an AST, builds Lamina IR for the whole program, and compiles that IR to a native executable.

Lamina turns the IR into assembly with compile_lamina_ir_to_assembly. The system gcc assembles and links the result with -no-pie, so weld is not on the link path. Its README describes the project as a demonstration of compiler construction, and its test results were recorded against an earlier Lamina release.

Evaluating

Rok, a language developed outside this project, has asked for Lamina as a backend and sent a list of what it would need. It is not compiling through Lamina today: the integration it wants starts with a library call that returns object bytes in memory, and that call does not exist yet. The request is tracked, and Rok moves to the list above if and when it ships against Lamina.

Adding a project

An entry is added after its call site has been read. To be listed, a project needs:

  • A public repository that contains the call into Lamina. A dependency declared in Cargo.toml that nothing calls does not count.
  • Lamina producing the output users run by default. A secondary path, or a JIT tier that hands work back to another engine, does not count as the chain.
  • A project that exists in code. A plan, or a mention in documentation, does not count.

Open an issue on the Lamina repository with the link, the Lamina entry point the project calls, the targets it builds for, whether it compiles ahead of time or at run time, and any part still handled by another toolchain. Rust projects call the Rust crate directly. Projects in other languages can use the C bindings. A demonstration is listed under Demonstrations.
